## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /api/dev/tamper/:entryId | Untrusted caller can corrupt ledger data |
| process env -> gate | Flag string parsing decides whether corruption is allowed |
| tamper helper -> DB | DDL on the append-only guard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | tamper route reachable in production | mitigate | server-side strict `NODE_ENV !== "production" && ENABLE_TAMPER_DEMO === "true"` checked first in route, evaluated per request; tests for unset/false/1/TRUE/production |
| T-04-02 | Tampering | triggers left dropped after failure | mitigate | single `.immediate()` transaction on app connection; trigger count asserted pre/post inside the transaction; rollback on mismatch; tests assert count 2 and plain UPDATE/DELETE throw |
| T-04-03 | Tampering | helper rewrites hash fields to hide tamper | mitigate | UPDATE sets only payload_json; test compares all other columns byte-identical |
| T-04-04 | Elevation of Privilege | tamper module importable by prod code paths | mitigate | dynamic import only after gate in route; grep acceptance restricts importers to route + seed |
| T-04-05 | Information Disclosure | 403 body reveals internals | accept | message only names env var and how to enable; no secrets; fits TAMP-02 requirement |
| T-04-06 | Spoofing/IDOR | entryId enumeration | accept | dev-only gated endpoint on local demo DB; integer ids validated by regex, unknown ids return generic 404 |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | plan installs no packages |
</threat_model>
