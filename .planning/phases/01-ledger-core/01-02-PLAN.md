<interfaces>
Contracts this plan creates (downstream plan 03 and later phases consume them):

hash.ts exports:
- GENESIS_HASH: string, 64 zero characters
- type LedgerAction = "PROJECT_CREATED" | "MILESTONE_APPROVED" | "CHANGES_REQUESTED"
- ACTIONS: readonly array of the three actions
- canonicalJson(value: unknown): string
- assertValidActor(actor: string): void  (throws Error when empty or contains "|")
- preimage(f: {index:number; timestamp:string; action:string; actor:string; payloadJson:string; prevHash:string}): string

verify.ts exports:
- type Hasher = (input: string) => string | Promise<string>   (lowercase hex SHA-256)
- type StoredEntry = {projectId:string; index:number; timestamp:string; action:string; actor:string; payloadJson:string; prevHash:string; hash:string}
- type EntryStatus = "ok" | "broken" | "untrusted"
- type VerifyResult = {valid:boolean; headHash:string; length:number; brokenAt?:number; entries:Array<{index:number; status:EntryStatus; expectedHash:string; storedHash:string; reason?:"index"|"project"|"prev-link"|"self-hash"}>}
- verifyChain(projectId: string, entries: StoredEntry[], sha256Hex: Hasher): Promise<VerifyResult>

The optional per-entry `reason` is an additive field (needed by AUDT-05 later); the locked VerifyResult fields are unchanged. Numbering: index is 0-based everywhere; brokenAt is that same 0-based index (UI in Phase 3/4 documents any display offset).
</interfaces>
